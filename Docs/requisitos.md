# Requisitos del portfolio de proyectos

## 1. Objetivo

Crear una aplicación web para registrar, consultar y controlar el portfolio de proyectos industriales.

## 2. Alcance de la primera versión

La primera versión debe permitir:

- Crear proyectos.
- Editar proyectos.
- Consultar una lista de proyectos.
- Filtrar proyectos.
- Abrir la ficha individual de cada proyecto.
- Mostrar un dashboard general.

## 3. Datos de cada proyecto

Cada proyecto debe contener:

- Código del proyecto.
- Nombre.
- Descripción.
- Project manager.
- Departamento.
- Tipo de proyecto.
- Estado.
- Fase.
- Rigurosidad R1, R2 o R3.
- Presupuesto aprobado.
- Importe comprometido.
- Importe gastado.
- Fecha de inicio.
- Fecha prevista de finalización.
- Porcentaje de avance.
- Prioridad.
- Observaciones.

## 4. Estados del proyecto

- Propuesta.
- En estudio.
- Aprobado.
- En ejecución.
- En pausa.
- Finalizado.
- Cancelado.

## 5. Fases del proyecto

- Idea.
- Definición.
- Ingeniería.
- Compras.
- Ejecución.
- Puesta en marcha.
- Cierre.

## 6. Dashboard

El dashboard debe mostrar:

- Número total de proyectos.
- Proyectos en ejecución.
- Proyectos retrasados.
- Presupuesto total aprobado.
- Importe total comprometido.
- Importe total gastado.
- Distribución por estado.
- Distribución por fase.

## 7. Diseño

La aplicación debe tener un diseño:

- Profesional.
- Sobrio.
- Adecuado para un entorno industrial.
- Claro y fácil de utilizar.
- Adaptable a ordenador y tableta.
- Sin elementos decorativos innecesarios.

## 8. Restricciones iniciales

- Utilizar únicamente datos ficticios.
- No conectar todavía datos reales de la empresa.
- No incluir contraseñas, claves ni credenciales.
- No utilizar información confidencial.
- Mantener el código modular y documentado.
- No conectar todavía una base de datos.
